how neural networks learn, no magic.

October 10, 2026

how neural networks learn, no magic.

You've probably heard these words a hundred times: gradient descent, derivatives, chain rule, backpropagation.

They can make learning feel like you're supposed to understand a secret language before you're allowed to understand AI.

But the central idea is much simpler than the vocabulary makes it sound.

A neural network makes a prediction. We measure how wrong it was. We work out which adjustable numbers contributed to that error. Then we change those numbers a little and try again.

That's the learning loop.

The mathematics tells us how to do each step reliably, especially when the network has millions or billions of adjustable numbers.

Let's build the intuition from the ground up. No skipped steps. No magic.

01. Start with the goal: make the error smaller

Imagine I give a model an input and ask it to predict a number.

  • →Input: a house with certain features
  • →Model's prediction: ₹50 lakh
  • →Actual price: ₹60 lakh

The model was ₹10 lakh off. We need a way to describe that mistake with a number. That number is the loss.

A loss function takes the prediction and the correct answer and tells us how bad the prediction was. The exact formula depends on the task, but the purpose is the same: give training a measurable target to improve.

For a simple example, use squared error:

L = (y_hat - y)^2

Here:

  • →y_hat is the model's prediction.
  • →y is the correct answer, also called the target.
  • →L is the loss.

If the prediction is 50 and the target is 60:

L = (50 - 60)^2 = 100

If the prediction improves to 58:

L = (58 - 60)^2 = 4

The loss has dropped from 100 to 4. The prediction is getting better.

Squaring makes the loss non-negative and penalizes larger errors more heavily. In real training, we often average the squared errors across examples, giving us mean squared error (MSE).

The mission is now clear: adjust the model so that its loss becomes smaller.

02. Gradient descent: finding the way downhill

Picture yourself standing somewhere on a foggy hill. You can't see the entire landscape, but you can feel whether the ground slopes up or down where you're standing.

What would you do to get lower?

  • 1.Check the slope under your feet.
  • 2.Take a small step downhill.
  • 3.Check the slope again.
  • 4.Repeat.

This is the intuition behind gradient descent.

Instead of walking across a physical hill, we're moving through a mathematical landscape. The height of the landscape represents the loss. Our position represents the values of the model's adjustable parameters, usually called weights and biases.

The gradient tells us which direction makes the loss increase most quickly. So, to move downhill, we step in the opposite direction.

The update rule for one parameter is:

theta_new = theta_old - eta dL/dtheta

Read it in plain English:

New parameter = old parameter − learning rate × slope of the loss with respect to that parameter.

  • →theta represents a parameter we can adjust.
  • →L is the loss.
  • →dL/dtheta is the gradient for that parameter.
  • →eta, the learning rate, controls the size of the step.

Why subtract the gradient? Because the gradient points uphill. Subtracting it moves us in the downhill direction, at least for a sufficiently small step near our current position.

A tiny example: L = x^2

Let's use the simplest possible loss landscape:

L(x) = x^2

Its derivative is:

dL/dx = 2x

Suppose we start at x = 3. The loss is 3^2 = 9, and the gradient is 2(3) = 6.

With a learning rate of 0.1:

x_new = 3 - 0.1(6) = 2.4

Our next loss is 2.4^2 = 5.76. It has gone down from 9 to 5.76.

Repeat the same process, one step at a time.

Step 0

  • →Current x: 3.000
  • →Loss: 3.000^2 = 9.000
  • →Gradient: 2 × 3.000 = 6.000
  • →Update: 3.000 − 0.1 × 6.000 = 2.400

Step 1

  • →Current x: 2.400
  • →Loss: 2.400^2 = 5.760
  • →Gradient: 2 × 2.400 = 4.800
  • →Update: 2.400 − 0.1 × 4.800 = 1.920

Step 2

  • →Current x: 1.920
  • →Loss: 1.920^2 = 3.686
  • →Gradient: 2 × 1.920 = 3.840
  • →Update: 1.920 − 0.1 × 3.840 = 1.536

Step 3

  • →Current x: 1.536
  • →Loss: 1.536^2 = 2.360
  • →Gradient: 2 × 1.536 = 3.072
  • →Update: 1.536 − 0.1 × 3.072 = 1.229

Each step takes us closer to zero, the minimum of this particular function.

Notice something important: as we approach zero, the gradient gets smaller. Our updates naturally become smaller too.

What can go wrong?

The learning rate matters.

  • →Too small: learning can be painfully slow.
  • →Too large: updates can jump past a good solution or make the loss grow instead of shrink.

Also, real loss landscapes are much more complicated than a perfect bowl. They can contain flat regions, steep regions, saddle points, and local minima. Neural-network optimization is not guaranteed to find the absolute global minimum. In practice, useful solutions can still be found with well-chosen optimizers, data, architectures, and training settings.

03. A real network has many knobs

Our first example had one adjustable number: x.

A neural network can have thousands, millions, or billions of parameters. Each weight can influence the final prediction, and each parameter may need a different update.

Imagine a soundboard with many knobs. One knob changes the bass, another changes the treble, and another changes the volume. If the sound is wrong, you need to work out how each knob affects the result.

In a neural network, the knobs are its trainable parameters. The mathematical tool that measures the effect of one parameter at a time is the partial derivative.

Suppose the loss depends on two parameters:

L(x_1, x_2) = x_1^2 + 2x_2^2

To find the partial derivative with respect to x_1, treat x_2 as a constant:

dL/dx_1 = 2x_1

To find the partial derivative with respect to x_2, treat x_1 as a constant:

dL/dx_2 = 4x_2

If we start at (x_1, x_2) = (3, 2), the loss is:

L = 3^2 + 2(2^2) = 17

The gradients are:

  • →For x_1: 2(3) = 6
  • →For x_2: 4(2) = 8

With a learning rate of 0.1, update both parameters using their own gradients:

x1_new = 3 - 0.1(6) = 2.4
x2_new = 2 - 0.1(8) = 1.2

The new loss is:

L = 2.4^2 + 2(1.2^2) = 8.64

It has dropped from 17 to 8.64 after one update.

For a model with millions of parameters, the idea is the same: calculate a gradient for each parameter, then update them together. The challenge is calculating all those gradients efficiently.

04. The difficult question: how do we find each parameter's gradient?

So far, the parameters directly appeared in our loss function. Neural networks are more involved.

A weight in an early layer does not usually affect the loss directly. It affects a hidden value, which affects another layer, which affects the prediction, which affects the loss.

The influence travels through a chain of calculations.

For example:

x -> u -> v -> y_hat -> L

If we want to know how a change in x affects the final loss, we need to account for every link in that chain.

This is where the chain rule comes in.

05. The chain rule: follow the influence backward

Imagine a team presentation goes wrong.

The presentation was confusing because the slides were confusing. The slides were confusing because the analysis was flawed. The analysis was flawed because the original data was incomplete.

To understand the effect of the original data collection on the final presentation, you trace the chain of influence.

The chain rule does something similar mathematically. It tells us how a change in an early variable affects a later result through intermediate calculations.

For a simple chain where u depends on x, and L depends on u:

dL/dx = dL/du * du/dx

In words:

Effect on the final result = effect at the final link × effect at the previous link.

Let's use a concrete example:

u = 2x
L = u^2

Substitute u = 2x, and we get L = (2x)^2 = 4x^2.

We can calculate the derivative directly:

dL/dx = 8x

Or use the chain rule:

dL/du = 2u
du/dx = 2

Therefore:

dL/dx = 2u * 2 = 4u = 8x

Same answer. The chain rule lets us break a complicated derivative into smaller, understandable pieces.

What if there are multiple paths?

A parameter can influence the final result through more than one path. When that happens, we calculate the contribution from each path and add them together.

That is important in neural networks, where values may feed into multiple later calculations. The gradient has to account for all those routes of influence.

06. Backpropagation: the efficient way to calculate gradients

Now we have the two ingredients:

  • →Gradient descent tells us how to update parameters once we know their gradients.
  • →The chain rule tells us how to calculate the gradients through nested calculations.

Backpropagation is the efficient procedure neural networks use to calculate gradients by applying the chain rule backward through the computation.

Let's separate the two directions.

Forward pass: data moves through the network to produce a prediction. We calculate the loss from that prediction and the target.

Backward pass: starting from the loss, we calculate gradients for the operations and parameters that contributed to it, moving backward through the computation.

Why backward? Because the loss is at the end. We can calculate how the loss changes with the prediction, then how the prediction changes with the previous layer, then how that layer changes with the one before it. Each step reuses gradients already calculated instead of starting over for every parameter.

A simplified view:

FORWARD PASS
input → layer 1 → layer 2 → prediction → loss
                                         |
BACKWARD PASS                            ↓
input ← gradients ← gradients ← gradients

The backward pass does not move the weights by itself. It calculates gradients. The optimizer uses those gradients to update the parameters.

That distinction is worth remembering:

  • →Backpropagation: calculate the gradients.
  • →Optimizer / gradient descent: use the gradients to update parameters.

07. A neural network is a nested function

This is the key connection.

A neural network may look like a complicated machine, but mathematically it is a composition of functions.

A simple network might calculate:

h_1 = f_1(x; W_1)
h_2 = f_2(h_1; W_2)
y_hat = f_3(h_2; W_3)
L = Loss(y_hat, y)

Each layer takes values from the previous step and transforms them. The final prediction is compared with the target to calculate the loss.

The inputs are the examples we are learning from. During ordinary supervised training, we do not change the training inputs to make the answer easier. We change the model's trainable parameters so the same kinds of inputs produce better predictions.

The parameters are the knobs. Backpropagation calculates how each knob affects the loss. Gradient descent uses those gradients to nudge the knobs.

That's the learning mechanism.

08. Let's build a tiny learning loop in Python

Before using a full neural-network library, we can demonstrate the core idea with one parameter. Suppose the model predicts:

y_hat = wx

We want it to learn the relationship y = 2x. We start with the wrong weight, calculate the loss, calculate the gradient, and update the weight.

# A tiny model: prediction = weight * input
x = 3.0
target = 6.0
weight = 0.0
learning_rate = 0.01

for step in range(100):
    # 1. Forward pass: make a prediction
    prediction = weight * x

    # 2. Loss: measure the mistake
    loss = (prediction - target) ** 2

    # 3. Backward math: derivative of loss with respect to weight
    # loss = (weight * x - target) ** 2
    # d(loss)/d(weight) = 2 * (prediction - target) * x
    gradient = 2 * (prediction - target) * x

    # 4. Gradient descent: update the weight
    weight = weight - learning_rate * gradient

print("learned weight:", weight)
print("final prediction:", weight * x)

The exact numbers depend on the learning rate and number of steps, but the weight should move toward 2 and the prediction toward 6.

This example calculates the derivative manually. For a real network with many operations, manually deriving every gradient would be impractical. Frameworks such as PyTorch build a computation graph and use automatic differentiation to calculate gradients for us.

Automatic differentiation is not guessing the gradients. It applies derivative rules—including the chain rule—to the operations that actually ran.

09. The training loop, step by step

Most neural-network training follows this cycle:

1. Get a batch of training examples
             ↓
2. Forward pass: make predictions
             ↓
3. Calculate the loss
             ↓
4. Backpropagation: calculate gradients
             ↓
5. Optimizer: update parameters
             ↓
6. Repeat

Let's translate each step.

  • 1.Get data. The model receives examples and their target answers.
  • 2.Predict. The input passes through the network. This is the forward pass.
  • 3.Measure error. The loss function compares predictions with targets.
  • 4.Calculate gradients. Backpropagation determines how each trainable parameter affects the loss.
  • 5.Update. The optimizer changes the parameters using the gradients.
  • 6.Repeat. The model processes more examples and continues adjusting its parameters.

One full pass through the training dataset is called an epoch. A single update is often called a training step or iteration, depending on the context.

The goal is not simply to make the model good at examples it has already seen. We want it to learn patterns that help it make useful predictions on new examples too.

10. Why not learn from just one example at a time?

There are different ways to decide how many examples to use before updating the parameters.

Online or per-example updates

The model processes one example, calculates its gradient, and updates the parameters immediately.

This can respond quickly to each example, but individual examples may point in different directions. The updates can be noisy.

Full-batch updates

The model calculates gradients using the entire training dataset, combines them, and updates the parameters once.

This uses information from all the examples for that update, but a large dataset can make it expensive in time and memory.

Mini-batch updates

The model processes a small group of examples, calculates the combined gradient for that group, and updates the parameters. Then it moves to the next group.

Mini-batches are a practical compromise between per-example and full-dataset updates. They make efficient use of hardware while giving the gradient a signal from multiple examples.

A group of 32, 64, or another number of examples is often called a batch. The appropriate size depends on the model, data, hardware, and training setup.

11. What changes when the network becomes enormous?

The core learning loop does not fundamentally change when we move from a tiny model to a large language model.

The system still:

  • 1.Runs a forward pass.
  • 2.Calculates a loss signal.
  • 3.Uses backpropagation to calculate gradients.
  • 4.Uses an optimizer to update parameters.
  • 5.Repeats over training data.

What changes is the scale and engineering around the loop.

Large models may have many more layers and parameters, require huge datasets, and train across multiple accelerators. Their training also needs careful memory management, numerical stability, data pipelines, distributed computation, monitoring, and evaluation.

The choices inside the loop can differ too:

  • →Activation functions determine how neurons transform their inputs. ReLU and GELU are common in neural networks; sigmoid is useful in certain settings, including some probability outputs.
  • →Loss functions depend on the task. Mean squared error is common for regression. Classification often uses cross-entropy-based losses.
  • →Optimizers such as SGD with momentum and AdamW use gradients in different ways to update parameters.
  • →Architecture determines how information flows through the network. A transformer, for example, uses attention and feed-forward blocks, but those trainable parts still learn through gradients and parameter updates.

Different models have different designs, data, and objectives. But gradient-based training remains a central mechanism behind many modern neural networks.

12. One important correction: training loss is not the whole story

It is tempting to think that if we keep reducing training loss, the model must keep getting smarter. Not necessarily.

A model can memorize its training examples without learning patterns that generalize. This is called overfitting.

That is why we also evaluate the model on data it did not train on. We may use a validation set to compare training choices and a separate test set for a final evaluation.

A lower training loss is useful evidence, but it is not proof that the model will perform well in the real world. We also need appropriate data, evaluation, and checks for the task we care about.

13. The whole thing, in five ideas

Let's bring everything together.

1. The model predicts. The forward pass turns input data into an output.

2. The loss measures the mistake. It gives us a numerical signal about how far the prediction is from the target.

3. The gradient tells us sensitivity. It tells us how the loss changes when a parameter changes a little.

4. Backpropagation calculates those gradients efficiently. It uses the chain rule to trace the loss backward through the network.

5. The optimizer updates the parameters. Gradient descent and related methods use the gradients to change the weights. Then the cycle repeats.

In one line:

Forward pass → loss → backpropagation → parameter update → repeat.

The next time you hear backpropagation, don't imagine a mysterious process that makes a model intelligent. Think of it as a systematic way to calculate how each adjustable number contributes to the final error.

Gradient descent tells the model how to use that information. Repeated across many examples, those small updates can produce a model that makes much better predictions.

No magic. Just functions, derivatives, data, and a lot of repeated updates.

The point of learning the fundamentals isn't to memorize the names. It's to understand what each part is doing well enough that the names stop being scary.
